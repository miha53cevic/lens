Read indicator — pick a direction

Each mock shows both sidebars (Code file tree · Summary list) and the header view-switch. Click any row to toggle it read/unread and watch the counters move. All three would persist per diff in localStorage (like the sidebar width) and reset when a file's content changes.

AViewed checkboxGitHub-PR style · explicit, dims what's done

How it works

  • Checkbox before each file / unit; checked rows dim + strike.
  • Viewed toggle in the code tab bar and the summary unit header, key m.
  • View-switch shows n / total with a thin green fill under each tab.

Trade-offs

  • Unambiguous — read means "I signed off".
  • Familiar to anyone who reviews PRs.
  • Needs a deliberate click per item.
  • Checkbox column adds visual weight to the tree.
BUnread dotsinbox style · lightest touch, auto-marks on open

How it works

  • Unread rows get an amber dot + bold name; it fades out once read.
  • Marked read automatically after the item is open ~1.5 s (or scrolled to the end); m toggles back to unread.
  • View-switch shows an unread badge; turns green ✓ at zero.

Trade-offs

  • Zero effort; reuses the existing amber "new" vocabulary.
  • Minimal visual noise once you're done.
  • "Opened" ≠ "reviewed" — skimming counts as read.
  • Amber dot may compete with the red needs-a-look dot.
CProgress ringsprogress-first · per-folder / per-section rollups + hide-read filter

How it works

  • Each row has a small hollow → filled mark.
  • Folders and summary sections get a ring + n/total, so you see which areas are done.
  • hide read toggle collapses finished items so the list shrinks to what's left.
  • Header carries one overall ring.

Trade-offs

  • Best sense of overall progress on big diffs.
  • "hide read" turns the sidebar into a to-do list.
  • Most UI to build (rollups, filter interplay with existing file filter).
  • Rings are small — less glanceable than a dim/strike.
